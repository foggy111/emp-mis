# ApiFox 测试记录

集合文件：

- `apifox/emp-mis.postman_collection.json`：按场景拆开的用例，ApiFox 选择「导入 Postman」即可。
- `apifox/emp-mis.openapi.json`：同一套资源的 OpenAPI 3 描述，用于生成接口目录。

变量 `baseUrl` 默认为 `http://localhost:8080`。Tomcat 的应用上下文需要是 `/`。先调用「登录」，并允许工具保存 Cookie，后面的员工接口才能通过拦截器。

本机（编写记录的环境）没有安装 MySQL、Tomcat 和 ApiFox，下面的「实际响应」一列是按代码推断的预期，不是一次真实联调。截图留空，回到自己的电脑跑完后补上。

统一响应形态：`{"code":200|500|401,"message":"...","data":...}`。

## 2. 参数校验

| 用例 | 请求要点 | 预期 message | 截图 |
| --- | --- | --- | --- |
| 空姓名 | `empName` 为 `""`，薪资 1000 | 员工姓名不能为空，`code=500` | 待补充 |
| 负薪资 | 姓名「测试」，`salary` 为 `-1` | 薪资不能为负数，`code=500` | 待补充 |
| 超长姓名 | 姓名 51 个「名」 | 姓名长度不能超过50，`code=500` | 待补充 |
| 超长部门 | `dept` 长度 51 | 部门长度不能超过50，`code=500` | 待补充 |
| 缺少薪资 | 不传 `salary` | 薪资不能为空，`code=500` | 待补充 |

这些失败应是 JSON，而不是 Tomcat 的 HTML 错误页。

## 4. 分页边界

库里执行完初始化脚本后有 4 名员工。下面的预期按这 4 行计算；如果你已经新增过员工，`total` 会变大。

| 用例 | 预期 | 截图 |
| --- | --- | --- |
| `page=0&size=5` | 不生成负偏移，按第 1 页返回，`current=1`，`records` 最多 5 条 | 待补充 |
| `page=9999&size=5` | `code=200`，`records` 为空数组，`total` 仍是全表匹配数 | 待补充 |
| `page=1&size=0` | `records` 为空，`total` 为匹配总数，不会把全表装进内存 | 待补充 |
| `page=1&size=-1` | 与 `size=0` 相同 | 待补充 |

## 5. 建议一并看的控制台

- 启动无 `ClassNotFoundException: DispatcherServlet`，无 `No ServletContext set`。
- 列表查询的 Log4j 输出里有 `LIMIT`。
- `mvn test`：不连数据库时应为通过，并有 1 个跳过的集成测试。连上数据库后再跑一次，可以看到回滚探针没有留下数据。
